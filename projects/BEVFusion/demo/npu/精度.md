### 2.0b unum_ops AscendC kernel 重编考古与坐标约定修复（2026-09-18 晚）

**背景**：移除分发器 x/y 列交换需将 unum_ops kernel 改为官方约定（coord[0]→H），重编后首次执行即
507015 AICORE 崩溃（MTE burst num incorrect）。

**考古结论**（git log + extra-info/data-dump 内核转储时间戳交叉验证）：
- 线上长期正常运行的二进制 = **9/4 3c7c9bd 时代构建**（固定 32 行 tile、coords 走 GM 标量读、
  旧约定 [y,x,z,b]，靠分发器列交换补偿）
- 9/6 的三个提交（70b5600 coords/starts/lengths UB 批量装载、dac1c36 UB 缓冲改 tilePoints=409 行、
  50a2322 OutputOffset/InBounds 约定改动）与 9/17 的 bev_pool 兼容提交**均未重编安装**，
  9/18 重编是它们的首次执行
- 崩溃根因：coords 批装 `DataCopy(coordsUb, ..., rowOff*4)` 每 16B/行，rowOff=409（奇数）→
  6544B 非 32B 倍数 → MTE 突发长度非法；与输入坐标值/约定**无关**（同 kernel 交换输入同样崩）

**修复**：kernel 回退 3c7c9bd + 仅叠加官方约定改动（OutputOffset `((bD+z)*H+x)*W+y`、
InBounds `bx<gridH, by<gridW` 两处），分发器直用原生 [x,y,z,b]（cat 列交换删除）。

**验证**：
- 张量级（/tmp/opencode/bpB.pt 真实数据）：vs QuickCumsum 参考差 768 cells / 0.0074%，
  max_abs 9.1——预存 kernel 竞态噪声级（同口径旧测量 9936 cells / 11.7），无转置系统差
- E2E demo：**48 dets / max 0.819478（与基线逐位一致）**，613-618ms（交换版 631-639ms）
- 全量回归未重跑：kernel 语义与旧二进制+交换配置完全等价（同约定、同数据路径），demo 级
  张量/E2E 验证覆盖；如需绝对确认可复跑 8 卡评测

### 4.1 旧 AscendC segment-sum kernel 预存非确定性（2026-09-18 根因定位；该 kernel 已于 2026-09-20 被原子加版取代）

**现象**：同进程、完全相同输入，连调 `bev_pool`（AscendC 路径）两次，输出不同——
10368000 元素中 9936 格（0.096%）bit 不同，max_abs ≈ 11.7，集中在 x=161-167 /
y=181-183 的固定 BEV 区域（约 124 格 × 80 通道）。

**定性**：kernel 内部并发写竞态（疑似 segment 跨核/chunk 边界时部分和覆盖，写序不定）。
**预存缺陷**——历史所有"运行间 score 噪声"（0.819478 vs 0.819399）的根源，非任何近期改动引入
（同输入重跑即复现，与代码版本无关）。

**影响评估**：传导到检测分数 ~1e-4 级 → mAP 粒度不可见。全量回归实证：AscendC
68.67/71.49 vs QuickCumsum 68.71/71.44（≤0.004，评测噪声）。**不影响数据集评测得分**。

**决策**：保持 AscendC 默认，不修 kernel。唯一代价：开发期 bit 级 A/B 验证不能走
AscendC 路径（会被噪声污染）——bit 级验证用 QuickCumsum（`BEVFUSION_BEV_POOL_BACKEND=torch`，
bit 确定性）+ AscendC 路径 E2E 检测数/top3 对比替代。

### 4.2 原子加 kernel 非确定性（2026-09-20，当前默认）

同输入重跑 max_abs **4.8e-7**——纯 fp32 原子加执行序重排（SetAtomicAdd 无丢更新，
4.1 的 11.7 级写竞态已随 segment-sum kernel 淘汰而消除）。与 mx_driving 同 class。
传导到检测分数 ~1e-4 级：demo E2E 48 dets / 0.819399 稳定，全量 mAP 68.74/71.49
（§1.0，与 QuickCumsum/GPU 基线噪声内一致）。bit 级 A/B 验证仍走 QuickCumsum 路径。

## 7. get_geometry NPU 精确路径探究（2026-09-18，"必须走 CPU 吗"的完整答案）

### 7.1 根因深挖：Cube fp16 机制的三个新事实

1. **任意尺寸 matmul 输出都落 fp16 网格**——不只大 bmm，3×3 小矩阵链同样中招
   （实测 `rots @ Ki` 输出 0.990234375 / 0.4033203125 等精确 fp16 台阶值，max_abs 4.6e-4）
2. **累加器也是 fp16**——补偿拆分（`M_hi@p_hi + M_hi@p_lo + M_lo@p`）无效：
   cell 错配 5.08% vs 直接折叠 4.96%
3. **逐元素 vector fp32 是真 fp32**（与 CPU 一致）——完全绕开 Cube 即精确

无效的开关（全部实测）：`torch.npu.config.allow_internal_fmt=False`、
`ACL_OP_SELECT_IMPL_MODE=high_precision`、fp64 bmm（310P 不支持）。

### 7.2 精确 NPU 配方（数学重构 + 混合放置）

- **CPU 侧（微秒级）**：3×3 小矩阵链——`inv(post_rots)`、`inv(intrins)`、
  折叠 `M = R @ Ki @ C3`、平移项 `c`、`bz`
- **NPU 侧（elementwise MAC，纯 vector fp32）**：
  `ray = M[...,0:1]*u + M[...,1:2]*v + M[...,2:3]`，再 `out = ray*z' + trans + c*z'`
  ——代数上把 `u*z` 大数齐次乘积消掉，且全程不出现 MatMul 节点

### 7.3 五种路径实测汇总（真实 demo 输入，B=1 N=6 D=118 H=32 W=88）

| 路径 | max_abs | cell 错配 | kept 翻转 | 耗时 |
|---|---|---|---|---|
| NPU fp32 vanilla（bmm×2） | 31.6m | 10.06% | 1958 | 12ms |
| NPU ray 折叠单 bmm | 0.087m | 4.96% | 914 | 9ms |
| NPU + 补偿拆分 bmm | 0.086m | 5.08% | 882 | 17ms |
| **NPU elementwise MAC（小链 CPU）** | **0.00002m** | **12 (0.0006%)** | **0** | 66ms |
| CPU 补丁（现役默认） | 0 | 0 | 0 | 44ms（串行探针口径；E2E 净成本实为 ~37ms，§7.5 overlap v2 已消除） |

### 7.4 决策

- **eager demo：保留 CPU 补丁（+ §7.5 overlap v2，现役默认）**——纯补丁 E2E 净成本
  实为 ~37ms/帧（"≈0"系 0.1s 计时误判，勘误见 §7.5）；v2 后 657ms，快于 NPU 几何
  路径的 664ms——NPU 精确配方本身新增 66ms 设备关键路径，不划算
- **OM 层A**：优先采用 7.2 配方（M/c/bz host 预计算 + 图内 Mul/Add 广播，
  不依赖 force_fp32）；备选 force_fp32 MatMul（历史 cos 0.9986）
- ray 折叠数学单独有价值：即使被迫走 Cube，误差从 31.6m 降到 0.087m（360×）

### 7.5 CPU 补丁的 D2H 阻塞与 overlap v2（2026-09-18 下午，勘误 §7.4 的"净≈0"）

§7.4 "净成本≈0"最初来自 0.1s 精度计时的误判（0.66/0.70s 都打印 0.7s）。ms 级
A/B 重测的真相与修复：

| 方案 | E2E（5 轮中位） | 几何 vs 纯 CPU 补丁 |
|---|---|---|
| 纯 CPU 补丁 | 694ms | 基准 |

- 纯补丁真实净成本 **~37ms/帧**：`.cpu()` D2H 在主流上排在 Swin 之后，必须等
  Swin 排干才开始 CPU 计算，期间设备空转
- v1 教训：主流上任何 D2H 都要等全部先前任务排干，提前 D2H 只让主机在 Swin
  入队前就被阻塞（更慢）。**主流 D2H 无法与设备重叠**
- v2 实现（`patch_get_geometry_overlap`）：矩阵诞生地在 `extract_feat`（metas
  numpy → `imgs.new_tensor`），hook 在构建前留存 numpy 副本；CPU 预计算
  （省 D2H 排干）；get_geometry 命中 stash 只做 H2D。几何输出与纯补丁**逐位一致**
- **附赠发现：下游 NPU 管线存在 ±1e-4 运行间 score 噪声**（几何逐位相同的两次
  运行，max score 0.819478 vs 0.819399）——今后精度对比的噪声地板
